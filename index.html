C.2.9. 图片与 Git LFS

  • 图片/ 下常见图片格式(png/jpg/jpeg/gif/webp/bmp/tif/tiff/avif/heic/heif/ico/psd) 由根目录 。gitattributes 配置了 Git LFS(svg 一行已注释掉)。
  • clone 前需装 git lfs，否则拿到的是指针文件；新图放进 图片/ 即自动走 LFS。
  • 引用图片用 image("图片/xxx。png")(路径相对当前 。typ 文件解析)。
  • HTML 导出会把图片内联成 base64，PDF 不会。make web 收尾时 脚本/抽取内嵌图片。sh 把这些内联图抽成 dist/图片/ 下的文件、页面改引 /图片/xxx 并加 loading="lazy"：与 图片/ 源文件逐字相同的(SVG 就是这种)直接用源文件名并从源目录 复制；对不上号的(Typst 会重新编码位图)解码落盘，按内容起名 内嵌-<长度>-<指纹>。<ext>， 免得同名却不同图被源文件顶掉。首页是全量入口，同一批图原本会在首页和章页里各嵌一份， 外链后浏览器只下一份。

  • 模板包 languages/zh。toml 的 [web] 段引用四个自托管 。woff2(正文/标题/粗体/评论)， 文件名固定；包内不含字体，由项目提供。

  • 源目录以 . 开头(默认隐藏)，与对外路径不同名：make web 把 。webfonts/*。woff2 拷到 dist/webfonts/(产物目录名固定为 webfonts，对应 /webfonts/… URL，勿改)； 。github/workflows/web。yml 在有字体时按字族各自取字子集化后再发布：从产物 assets/underhell。css 读 @font-face 与 --uh-*-font，按选择器(标签 / 。class / [class^="…"])判定哪些元素由哪个族渲染，每个字体只带它真正要显示的字 —— 标题/粗体/评论三族只需各自那几百字，正文族仍用全站并集。 任何环节认不出来(CSS 缺失、@font-face 对不上、选择器形态不认识)一律退回全站并集； 子集写完再用 cmap 复核，缺字形就重做。宁大勿坏，最坏等于旧行为，不会发出未子集的全字库。

C.2.11. 语法规范

中文：以直陈、白描为基本写法。少用状语、补语和副词，只保留有实际信息的修饰。 优先保留原本自然的语言习惯，不为深刻、优美、完整而润色。保持自然的长短句变化， 拒绝套用总分总结构，不强行总结或升华。

反例：「这个方法值得继续研究」不要写成「这个方法还有值得深入挖掘的空间」。

English： Use direct statements and plain prose. Minimize adverbials， complements， and adverbs； use them only when they add concrete information. Preserve the writer’s natural voice. Do not polish simple language to sound deeper， more elegant， or more complete. Keep natural variation in sentence length. Avoid rigid summary structures and forced conclusions.

C.2.12. 发布网页

make web 的 dist/ 是纯静态站点(。webfonts/ 有字体时产物含 webfonts/，有图片时含 图片/)。 推送 main 后 。github/workflows/web。yml 会重建、把页面引用到而产物缺失的图片从 图片/ 补进 dist/图片/、按字族各自用字子集化字体，并强推 web 分支；托管平台(Cloudflare Pages / EdgeOne Pages)绑定 web 分支并关闭平台侧构建即可。分平台步骤见根 README。md「部署网页」。

/图片/* 会被 CDN 按 URL 缓存：matplotlib 重跑覆盖同名源图时，产物字节变了但 URL 没变， 平台侧可能要手动清缓存才见效。
